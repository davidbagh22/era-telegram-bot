## Роли

- Только председатель назначает/заменяет/снимает руководителя, управляет полномочиями всего отдела, видит полную аналитику и исправляет ошибочные начисления отдельной журналируемой операцией.
- Бот: Управление → Департаменты → Медиа → Руководитель; Назначить / Заменить / Снять / Посмотреть. Ввод Telegram ID зарегистрированного пользователя и подтверждение перед изменением. Идентичность председателя устанавливать из действующего доверенного механизма, не по имени/изменяемому username и не считать любого администратора председателем.
- Назначенный руководитель получает функциональную роль media_leader и «Управление медиа» в обоих интерфейсах: задания, приёмка, состав, ответственные, контент-план, база знаний, объявления, приглашения, аналитика. Не вправе назначать другого руководителя. После снятия доступ прекращается немедленно.
- Ответственные назначаются руководителем только на свою область ЭРА/КСООРС и функцию; это не полномочия всего отдела. Существующие глобальные роли сохраняются.
- Участник получает/принимает задания, откликается, сдаёт версии, получает замечания, баллы после проверки, портфолио и собственную статистику. Членство в нескольких департаментах разрешено.

## Задания, сдача, баллы и портфолио

Общий сервер и БД для бота/Mini App. Поля: название, описание, направление ЭРА/КСООРС, категория фото/видео/монтаж/текст/дизайн/интервью/другое, персональное/свободное, исполнитель/места, срок Asia/Yerevan, баллы, приоритет, платформа, материалы/ссылки, критерии приёмки, автор.

Персональное: уведомление Принять / Не могу выполнить / Подробнее; отказ уведомляет руководителя, поддержано переназначение. Свободное: публикация в «Задания», Взять / Подробнее; сервер проверяет членство, свободные места, повторный отклик. Конкурентные отклики не превышают вместимость.

Статусы: черновик, опубликовано, в работе, на проверке, на доработке, выполнено, отменено. Просрочка — отдельный признак, без потери истории статуса. Сдача: файл/фото/видео/ссылка/текст. Руководителю уведомление; принять или вернуть с комментарием. Версии и история приёмки сохраняются.

Баллы задаются при создании, начисляются только после приёмки через общий защищённый ledger. Повторы/двойные нажатия не начисляют снова. Групповое задание учитывает каждого исполнителя. Исправления — отдельные audit/ledger операции, без переписывания истории.

После приёмки работа идемпотентно попадает в существующее портфолио: название, категория, направление, дата, роль, результат, баллы, ссылка публикации. Публичность только по приватности/согласию пользователя.
