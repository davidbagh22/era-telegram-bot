# Единые определения аналитики ЭРА 2.0

Контракт реализации; наличие документа не означает завершение расчётов. Часовой пояс Settings.timezone (production Asia/Yerevan). Окна [начало;конец), одинаковая длительность 7/30/90 дней и непосредственно предшествующее окно. Хранение/сравнение UTC, календарные даты переводятся из зоны организации. Всегда показывать период и ограничения данных.

- Действующие участники: approved, не blocked/archived, participation_mode != EXITED. Цифра на дату — только если существует историческое состояние; иначе текущая база и недоступная историческая динамика.
- Новые участники: первое достоверное одобрение за период по audit; при отсутствии истории отдельно новые регистрации по created_at. Не смешивать показатели.
- Подтверждённая активность: уникальный участник с подтверждённым посещением/принятым заданием/подтверждённым вкладом либо завершённым результатом проекта за период. Регистрация, открытие бота, идея, простое одобрение проекта и сертификат не являются дополнительным результатом. Не считать повторные ledger записи отдельными участиями.
- Цифровая активность: отдельный показатель взаимодействий/цифровых бонусов; не входит в verified KPI. Ответственность: действующее назначение с датами/областью, отдельно от роли лидера и уровня развития.
- Удержание: участники с verified результатом в предыдущем окне, имеющие результат в текущем / verified предыдущего окна. Это activity retention, не удержание членства. При нулевой базе null с причиной, не 0%.
- Путь 90 дней: когорта зарегистрированных за 90 дней; одобрение, первый и второй distinct verified результат, переходы в активный статус/лидеры только по достоверной истории. Текущая роль не доказывает дату перехода. Конверсия и длительность только для наблюдаемых этапов; исторически неполные записи и незавершённые окна помечать.
- Проведённые мероприятия: completed/report_submitted с фактической датой в окне. Явка: attended / зарегистрированные с обязательством прийти, исключая waitlist и отменённые регистрации; правило denominators сохраняется единым в UI/Excel. Отзывы считать по реально оставленным ответам, без нулевых оценок за отсутствие.
- Активные проекты: общий набор approved/in_progress; черновики, рассмотрение и завершённые исключены. Каждый статус также показывается отдельно. Участников и подтверждённый вклад считать раздельно.
- Задачи требуют внимания: distinct задачи с просрочкой, блокером или ожидающим проверки результатом; объединение без двойного итога. SLA из существующих настроек/процессов, не выдуманный норматив.
- Динамика: абсолютная разница; процент только при известной ненулевой базе и одинаковых формулах/области. Нормы предупреждений только из явных правил; нет нормы — нет выдуманного сигнала.
- Руководитель видит агрегаты/детали только своей действующей области; экспорт использует ту же авторизацию и snapshot. Председатель/уполномоченный администратор — общую разрешённую область. Без субъективного рейтинга руководителей.

Один расчётный snapshot с metadata и drilldown IDs питает Telegram, API, отчёт и Excel. Списки могут иметь пагинацию; организационные итоги — SQL aggregates без случайных limit. Безопасные null/reason нужны для отсутствующих временных меток и истории. Старые API/листы сохраняются совместимыми.

Реализованный первый пакет: analytics_snapshot_service; dashboard active_base сохраняет явное окно 14 дней, health 7/30/90 и efficiency 30 — одинаковые verified facts и текущая eligible база, без должностей/цифровых баллов. Health retention = пересечение активных когорт 30/30 дней; при пустом знаменателе API null, display «Нет данных», score null. Legacy Excel balance описан как баланс, а прежний лист «Воронка роста» явно помечен текущими срезами, не исторической конверсией.

Рост 90 дней: когорта User.created_at [now-90d;now), первое audit user.approved после регистрации, первый/второй distinct result_key event/task/project после одобрения; ledger бонусы и structured confirmation одного объекта дедуплицированы. Старые ledger без object ID не доказывают повтор. Последующие activist/leader только по audit после предыдущего этапа, медиана длительности наблюдаемых пар. Текущее одобрение без истории показывается отдельно; незавершённый этап не называется уходом. Разрывы доступны по 10 имён только через действующий admin guard; API/Excel тот же GrowthSnapshot.

Мероприятия: completed/report_submitted за полные локальные дни; denominator registered/will_come/attended/no_show (без waitlist/cancelled/not_coming); first/returning по первому известному attended event_date, не по баллам. Feedback average только по реальным отзывам; coverage = отзывы именно attended / attended. Числитель/знаменатель/visitor cohorts рассчитываются одним SQL statement. Health/efficiency используют те же факты.

Проекты: current draft/review/approved/in_progress/completed stocks имеют previous=NULL без исторических снимков. Изменение есть для created_at, contribution_confirmed_at, milestone.completed_at. Просроченные этапы только approved/in_progress, без completed/cancelled. «Без результатов за период» — проект существует весь период и нет подтверждённого вклада/этапа/принятого задания; это повод проверить процесс, не норматив качества. Delivery warnings используют существующие receipts failed/blocked/unreachable/uncertain/conflict за 30 дней; чтение ничего не отправляет и не создаёт дубли.
