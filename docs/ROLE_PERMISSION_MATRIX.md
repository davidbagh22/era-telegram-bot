# Фактические права и границы доступа

Широкая роль, точечное разрешение и scope — разные проверки. Наличие кнопки или имени разрешения в UI не разрешает действие на сервере. Корневой native admin router сейчас допускает только полных администраторов.

## Согласованные роли и существующая модель

| Роль из Master-ТЗ | Действующий эквивалент | Проверенная граница / остаток |
|---|---|---|
| Суперадминистратор | settings.admin_ids | Полный доступ; защищён от понижения/блокировки через бота |
| Администратор | users.role=admin | Полный активный административный профиль; нельзя отключить последнего администратора |
| Руководитель департамента | Role.HEAD и существующие UserOffice | Не равен глобальному администратору; scoped actions требуют контекста объекта |
| Редактор мероприятий | events.manage | Для общих API-операций нужен global/0. Native composer дополнительно ограничен своим флагом и маршрутом |
| Модератор заявок | applications.review в каталоге | Сам код разрешения не открывает native admin root; отдельный guarded маршрут ещё требуется |
| Модератор чатов | chat.moderate и действующие правила Telegram | Не получает права на пользователей/баллы/настройки чатов. Решения человека-модератора защищены |
| Контент-редактор | Существующие content permissions и literature editor | Native editor пока full-admin; scoped редакторский доступ не объявлен завершённым |
| Участник | Role.PARTICIPANT, approved | Собственный профиль/регистрации/проекты/обращения, без административных полномочий |

Новые роли не создаются параллельно grants/appointments. Расширение делегированных native-маршрутов — оставшаяся задача; не ослаблять общий admin filter до «есть любое разрешение».

## Общие операции без контекста объекта

| Операция | Глобальное разрешение для делегата |
|---|---|
| Просмотр всех участников | people.view или people.manage |
| Управление участниками | people.manage |
| Общие операции мероприятий и экспорт участников | events.manage |
| Общие операции задач | tasks.manage |
| Партнёры/предложения | partners.manage |
| Начисление баллов в admin API | points.award; people.manage не заменяет его |
| Настройки общих Telegram-чатов | Дополнительно native admin root; department people.manage не допускается внутренней проверкой |

Используется authorization_service.active_global_permissions: активный grant с scope_type=global, scope_id=0. Неполные/неизвестные scopes отвергаются. active_permissions и effective_permission_names остаются перечнем возможностей для UI; их нельзя применять как глобальную авторизацию.

leadership_permission_service.has_scoped_permission без scope означает глобальную операцию. Региональное разрешение действует при явном совпадении scope_type/scope_id. Это не подмена будущих объектных проверок общим bool.

## Проверки и приёмка

tests/test_global_permission_scope.py проверяет отказ department grants в глобальных действиях, сохранение global grants, неполные поля, запрет произвольного начисления и настоящий HTTP 403 до чтения списка участников. Существующие тесты должностей, ролей, revoked grants и native root сохранены.

17.10.2026 read-only проверка production: два активных grants, оба global; scoped grants этих типов не обнаружены. Профили и идентификаторы пользователей не публикуются. Изменений schema/data нет. Откат кода сохраняет grants, но возвращает прежнюю более широкую проверку; предпочтительнее исправление вперёд. Готовность production подтверждается CI/Render-протоколом.
