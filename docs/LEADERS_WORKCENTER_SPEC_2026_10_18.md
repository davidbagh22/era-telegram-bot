# Лидеры ЭРА: итоговое ТЗ и решения по прежним PR

Основание: пользователь поручил самостоятельно проанализировать бота, ответить на вопросы по устройству и выполнить актуальные незакрытые PR. База реализации — main afea0c8, включая выпущенный PR #351. Документ описывает реализуемый контракт; выпуск подтверждается отдельно успешными проверками окончательного коммита и Render LIVE.

## Организация и права

Статус участника, должность, уровень развития и разрешения — отдельные данные. Назначение лидером не назначает руководителем направления. Уровень развития «Лидер» по подтверждённым достижениям также не выдаёт административные права.

| Кто | Область | Задачи и сообщения | Назначение лидера |
|---|---|---|---|
| Председатель и заместитель председателя | Всё сообщество | Создание, контроль, проверка результатов | Да |
| Администратор | Всё сообщество | Полный доступ | Да |
| Руководитель внутренних дел / внешних связей / Медиа | Своя подтверждённая область | Задачи и сообщения своей команде | Нет |
| Пресс-секретарь | Явно выданная область и разрешения должности | Согласно разрешениям | Нет |
| Лидер / активист | Свои и доступные свободные задачи | Принять, отказаться до начала, выполнить, сообщить о проблеме | Нет |

Действующие назначения проверяются с датами и активностью. Название роли «Лидер» само по себе не даёт права рассылать всем или проверять чужие работы. HEAD ограничен связанными отделами/направлениями. Дополнительные полномочия задаются существующими scoped grants / permission_template, без скрытого назначения людям. Добавлена штатная должность «Пресс-секретарь», без автоматического назначения владельца. Если человек совмещает должности, их активные разрешения объединяются с сохранением областей.

## Админка

Одна точка входа: Управление ЭРА → Люди → Лидеры. Четыре вкладки: Команда, Задачи, Рассылки, Пульс. Старый дублирующий пункт рабочего центра убран из списка работы. Общесистемные «Задания» и «Центр связи» сохранены для других аудиторий.

Команда: поиск одобренных участников, страницы состава, действующие должности, подтверждение назначения/снятия статуса лидера. Проверяется ожидаемая текущая роль. Нельзя заменить руководящую роль этим действием. При снятии статус становится «Активист»; баллы и история сохраняются. Назначение должности выполняется существующим разделом «Должности».

Задачи: название, результат/описание, команда, конкретный исполнитель или свободная задача, необязательный срок. Дополнительно — приоритет и баллы (0–1000, исторический default рабочего центра 10). В старом публичном каталоге сохраняются прежние утверждённые пресеты; экономика не унифицируется скрытой миграцией. Перед созданием — предпросмотр. Фильтры: активные, свободные, на проверке, просроченные, нужна помощь, выполненные, все. Карточка содержит результат, комментарии, историю, состояние доставки и ссылку в чат.

Рассылки: текст до 2800 символов, аудитория, способ доставки, кнопка ознакомления, предпросмотр и явное подтверждение. Способы: чат / лично / оба. Для отдельной команды — только личная доставка. История показывает отправки, недоступные аккаунты, неизвестный исход и ознакомления отдельно. Пауза, продолжение и отмена оставшихся доступны автору в его области и руководству.

Пульс: действующий недельный отчёт, решения и ответственные. Исторические отчёты, ответы и календарь не преобразуются.

## Личный бот и чат

В боте: кнопка «Лидеры», команды /leader и /leaders, ссылка `?start=leaders`. Открывается нативное меню без обязательного перехода в Mini App. Доступны свои/свободные/завершённые задачи; руководителям — создание и проверка; руководству — команда и назначение лидера; уполномоченным — рассылки.

Адресная задача сначала предложена: исполнитель начинает либо отказывается до начала. Свободную задачу атомарно забирает один человек. После начала передача через руководителя. Исполнитель сдаёт текст/файл, может обозначить блокер или вопрос. Результат принимает другой уполномоченный руководитель либо возвращает с обязательным комментарием. Самопроверка запрещена. После приёмки начисление выполняет общий сервис; старые кнопки не меняют закрытый результат и не начисляют второй раз.

Task остаётся единственным источником состояния. Бот, админка и карточка чата используют общие сервисы. Существующие topic_id/message_id сохраняются, карточки редактируются. В обычном чате создаётся одна переиспользуемая панель. При неопределённом исходе создания темы/карточки автоматическое повторное создание блокируется для ручной сверки. Чат лидеров должен отличаться от общего чата. Если тема рассылки отсутствует, сообщение не публикуется случайно в General.

Личный доступ к рабочему центру возможен для назначенных лидеров; право заполнять Пульс по-прежнему определяется действующим членством чата. Эти две аудитории намеренно не смешиваются. Назначение лидером не приглашает в Telegram и не снимает ограничения чатов.

## Доставка и повторные действия

Используются существующие Broadcast, NotificationDelivery, TaskDelivery и audit. Аудитория рассылки фиксируется при подтверждении. Повторный request_key с тем же содержимым возвращает ту же сущность, с иным содержимым — ошибку. На PostgreSQL создание сериализуется advisory lock. Отправки используют существующий общий worker и стабильные ключи. Неизвестный исход не повторяется автоматически. Пауза/отмена, принятые во время отправки, имеют приоритет; уже летящий запрос отозвать нельзя.

Подтверждение «Ознакомился» принимается только для фактически отправленного сообщения и проверенного аккаунта; успешная отправка не считается прочтением.

Production-дефект напоминаний: ключ `leadership-pulse-cycle:4:first:*` уже существовал со статусом sent, но текущий генератор давал иной текст. Повторная генерация вызывала payload conflict каждые пять минут. Исправление: проверять терминальный receipt до генерации, для новых отправок сохранять неизменяемый снимок текста; не переписывать исторический ledger и не создавать новый ключ для обхода защиты.

## Остаток прежнего ТЗ

Авторитетный полный перечень — [MASTER_REMAINDER.md](MASTER_REMAINDER.md). Этот пакет не объявляет всё Master-ТЗ завершённым.

- Реальная приёмка в Telegram: председатель/заместитель, руководитель своей команды и исполнитель, включая файл, возврат и повторную кнопку. Автоматические тесты и FakeBot не заменяют приёмку на устройствах.
- Независимое S3-совместимое хранилище резервных копий и проверка восстановления именно оттуда: требуются настроенные владельцем secrets; действующий backup/restore не отключать.
- Обращения сохраняют текущий режим TESTERS; расширение аудитории выполняется после реальной приёмки, без самовольного включения всех флагов.
- Редакционные материалы, юридические тексты, календарь, сертификаты и локализации требуют проверки содержания/приёмки. Массовые публикации и рассылки ради проверки не выполняются.
- Отдельная приёмка процесса проектов и портфолио по MASTER_REMAINDER.md, включая разные роли. Назначение лидера не означает завершение этих процессов.

## Приёмочные проверки и выпуск

Обязательны: backend suite, lint correctness, frontend build и браузерный сценарий четырёх вкладок/создания задачи/назначения лидера. PostgreSQL probe проверяет восемь параллельных подтверждений задачи/рассылки, захват одной свободной задачи и один переход роли; прежний probe — однократное решение и начисление. Запуск этих probe разрешён только на изолированной era_test, без Telegram.

Условие выпуска — успешные CI окончательного head, объединение PR и Render LIVE именно объединённого коммита, health/ready и чтение журналов после выпуска. До этого новая функциональность обозначается только как подготовленная. Новая схема и преобразование существующих данных не требуются. Откат к afea0c8 сохраняет IDs, задачи, аудит и ledger; новые кампании при необходимости ставятся на паузу через штатное управление.
