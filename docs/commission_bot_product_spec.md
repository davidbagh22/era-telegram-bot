# МОЛОДЁЖЬ ВКСРС — production ТЗ

## 1. Назначение
Telegram-бот — единая онлайн-система Комиссии по взаимодействию с молодёжью для участников, редакторов, модераторов, администраторов и владельца. Все мероприятия считаются онлайн. QR/check-in и Mini App не входят в продукт.

Цель: один понятный путь от публикации и сегментации аудитории до регистрации, участия, обратной связи и управленческой аналитики.

## 2. Принципы
- Telegram — основной канал.
- Никакая массовая отправка не запускается без предпросмотра, подсчёта аудитории и явного подтверждения администратора.
- Страна никогда не определяется по языку Telegram; используется только страна профиля.
- Для узкой географии глобальный чат не включается автоматически.
- Личные информационные рассылки получают только пользователи с telegram_opt_in=true.
- Сервисные уведомления по собственной регистрации отделены от общих рассылок.
- Все повторяемые операции должны быть идемпотентны.
- При сетевых ошибках Telegram выполняются ограниченные повторные попытки.
- Сценарий не должен «запирать» пользователя: главное меню безопасно закрывает старый незавершённый flow, кроме обязательного первичного onboarding.

## 3. Роли
### Viewer
События, регистрации, профиль, уведомления, обращения, ежемесячные опросы.

### Editor / Moderator
Создание публикаций, работа с участниками/регистрациями, обращения. Нет финального права массового запуска, если это не разрешено ролью.

### Admin
Согласование, публикации, сегментированные рассылки, чаты/каналы, аналитика, обращения, отчёты эффективности.

### Owner
Все права, управление командой и ролями.

## 4. Профиль участника
Обязательная основа: Telegram ID, имя, регион, страна, возраст.
Расширенный профиль: город, организация/вуз/место работы, статус, телефон, email, соцсеть, интересы, часовой пояс, согласия.

Поля контактов допускают пропуск, чтобы не снижать конверсию регистрации. Профиль заполняется один раз и повторно используется в заявках.

## 5. Регистрация на события
- Быстрая регистрация в 1 клик.
- Расширенная анкета.
- До 5 дополнительных вопросов конкретного события.
- Дедлайн.
- Ограничение мест.
- Лист ожидания и автоматическое повышение при освобождении места.
- Отмена пользователем.
- Список и Excel-выгрузка для команды.
- Источник регистрации хранится отдельно.
- Персональные данные доступны только сотрудникам с соответствующими правами.

## 6. Онлайн-событие
Жизненный цикл: Draft → Pending approval → Approved/Scheduled → Published → Completed/Archived либо Cancelled.

Для события должны поддерживаться:
- локальное время и часовой пояс;
- ссылка подключения;
- дедлайн регистрации;
- подтверждение участия «Буду / Не смогу / Пока не уверен»;
- напоминания;
- ссылка подключения ближе к началу;
- вопросы спикеру;
- FAQ;
- материалы/запись после завершения;
- обратная связь после события;
- добавление в календарь;
- отмена с уведомлением зарегистрированных;
- редактирование опубликованной информации и обновление доставленных сообщений, когда это позволяет Telegram;
- архив прошедших событий;
- избранное.

## 7. Публикации
Типы: мероприятие, онлайн-встреча, возможность, конкурс, объявление/важное сообщение.

Процесс:
1. Редактор создаёт материал пошагово.
2. Черновик сохраняется.
3. Предпросмотр.
4. Отправка на согласование.
5. Администратор: одобрить сейчас, запланировать, вернуть с комментарием, отклонить.
6. При публикации создаются напоминания и delivery records.
7. Доступна история изменений и аудит действий.

## 8. Чаты и каналы
Подключение:
1. Добавить @MVKSRS_bot администратором.
2. Bot получает membership event и создаёт target со статусом pending.
3. Администратор в боте задаёт:
   - сеть: Commission / MDS / Partner;
   - географию: Global / Region / Country;
   - назначение: General / Events / Opportunities / Education / Announcements;
   - теги: youth / students / leaders / volunteers / media / partners;
   - проверяет права публикации.
4. Только после «Подтвердить» target используется в рассылках.

Правило соответствия:
- global campaign → все подходящие approved targets;
- region campaign → targets этого региона + country targets стран региона;
- country campaign → только target конкретной страны;
- global target не получает узкую региональную/страновую кампанию автоматически.

## 9. Сегментированные рассылки участникам
Фильтры:
- весь мир / регион / страна;
- возрастные группы;
- статус участника;
- интересы;
- активность;
- теги;
- в дальнейшем — участие в конкретных событиях и источники регистрации.

Каналы:
- личные Telegram-сообщения;
- approved чаты/каналы Telegram;
- оба канала одновременно.

Перед отправкой показываются фактические counts: users + targets. Если аудитория равна 0, запуск запрещён. После отправки видны sent/failed и повторные попытки.

## 10. Ежемесячный пульс эффективности
Автоматическая отправка активным активистам: 5-го числа каждого месяца в 19:00 Asia/Yerevan.

Критерий активной аудитории: onboarding complete + opt-in + хотя бы один сигнал активности: взаимодействие за 60 дней, регистрация за 180 дней, staff role или tag=activist.

Каждый опрос: 4 оценки по шкале 1–5 + необязательный открытый комментарий. Ответ можно продолжить после выхода. Один пользователь — один ответ на один run. Можно отказаться только от ежемесячных опросов, не отключая сервисные уведомления.

### 10 тем, ротация по месяцам
1. Мы и сообщество — вовлечённость и чувство принадлежности.
2. Коммуникация без шума — понятность и своевременность информации.
3. Ценность возможностей — практическая полезность возможностей.
4. Онлайн-события — качество и применимость встреч.
5. Доверие и обратная связь — доверие к команде и feedback loop.
6. Личный рост — знания, навыки и развитие.
7. Атмосфера сообщества — уважение, включённость, безопасность общения.
8. Связи без границ — международные связи и совместные проекты.
9. Инициатива и проекты — возможность предлагать и реализовывать идеи.
10. Результат и следующий шаг — общий impact и приоритеты.

Первый автоматический run: 2026-10-05, затем раз в месяц. После 10 тем цикл повторяется, что позволяет сравнивать год к году.

## 11. Аналитика
Админ-dashboard:
- участники и заполненность профилей;
- страны/регионы;
- регистрации и уникальные участники;
- доставка/ошибки;
- подключённые targets;
- обращения и скорость ответа;
- интересы;
- события;
- ежемесячный pulse: охват, response rate, средние оценки по каждому вопросу и динамика.

Excel: Dashboard, Participants, Events, Registrations, Distribution, Support, Countries, Interests и отдельный файл/раздел Movement Effectiveness.

## 12. Поддержка
Пользователь: категория → вопрос → ticket.
Сотрудник: inbox → диалог → ответ → закрытие.
Пользователь может продолжить цепочку до закрытия.

## 13. Надёжность
- delivery dedupe keys;
- три попытки при временных сетевых ошибках;
- Telegram RetryAfter учитывается;
- scheduler восстанавливает due work после перезапуска;
- survey run unique by month_key;
- campaign delivery unique by campaign/channel/recipient;
- пустая аудитория никогда не отправляется;
- старый flow не блокирует навигацию;
- ошибки одного recipient не останавливают всю кампанию.

## 14. Privacy
- контакты и анкеты используются только для организации работы и событий;
- opt-out для общих рассылок и отдельно для monthly pulse;
- хранится факт согласия;
- Excel доступен admin/owner;
- тексты support-переписки не должны попадать в общий аналитический экспорт без отдельной причины;
- предусмотрен запрос на удаление/очистку данных.

## 15. WhatsApp
Автоматическая WhatsApp-рассылка не считается production-ready без официального WhatsApp Business API и credentials. До подключения API допустим только ручной share/pre-filled flow. Нельзя выдавать placeholder за работающую автоматизацию.

## 16. Матрица сценариев («1000 вопросов»)
Перед выпуском каждый feature проверяется через комбинации:
- role: viewer/editor/admin/owner;
- state: clean/onboarding/draft/registration/support/survey/segment;
- audience: empty/one/many/country/region/global;
- target: pending/approved/disabled/no-post-rights;
- event: future/due/past/cancelled/full/waitlist;
- delivery: success/RetryAfter/network failure/permanent failure/restart;
- user: opt-in/opt-out/profile incomplete/blocked;
- action: start/back/cancel/menu/retry/edit/approve/schedule/send.

Ожидаемый инвариант: ни одна комбинация не должна создавать скрытую массовую отправку, дубликат, потерю регистрации или состояние, из которого пользователь не может выйти.

## 17. Acceptance criteria
- `/health` основного Render-сервиса остаётся 200.
- Commission polling стартует без fatal exception.
- DDL идемпотентен на существующей production schema.
- Owner сохраняет owner role после миграции.
- Основное меню открывается из незавершённого старого wizard.
- Регистрация, support, analytics XLSX продолжают работать.
- Узкая country/region segment не включает global target.
- Перед segmented send отображается live estimate и требуется explicit confirm.
- Monthly survey создаётся максимум один раз на month_key и не отправляется до заданного времени.
- Survey opt-out не отключает сервисные уведомления.
- Повторный scheduler/deploy не создаёт дубликатов survey/campaign deliveries.
