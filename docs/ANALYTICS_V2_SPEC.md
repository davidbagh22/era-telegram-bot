# ЭРА — Analytics 2.0: техническое задание
Статус: проектирование и безопасная реализация в отдельной ветке. Продакшн не менять до тестов.
Дизайн: гибрид вариантов 2 (графики), 3 (управление), 4 (BI).

## 1. Цель
На мобильном экране за 30 секунд показать состояние организации, проблемы и действия. Сохранить существующие 59 метрик в детализации, не выводить их одним длинным списком.

## 2. Навигация
Верх: «Аналитика», селектор периода 7/30/90 дней и произвольный интервал, «Сравнить», «PDF».
Вкладки: Обзор, Люди, Деятельность, Команда, Возможности, Отчёты. Активная вкладка видима; меню горизонтально прокручивается; доступность с клавиатуры.
Обзор: 4–8 KPI, динамика участников, проблемы по приоритету, пульс с объяснением методики, действия.
Люди: текущая база, новые, роли, департаменты, подтверждённые действия, удержание только при корректной когорте.
Деятельность: события, явка, проекты, задачи, сроки, реальные результаты.
Команда: департаменты, ответственные, загрузка, исполнение, медиа.
Возможности: партнёры, предложения, заявки, конверсии.
Отчёты: PDF, Excel, выгрузки объектов, журнал сформированных отчётов.

## 3. Правила метрик
Модель каждого показателя: id, label, value, unit, period, previous_value, delta, numerator, denominator, data_state, source, updated_at, explanation, drilldown.
data_state: valid | empty | insufficient | unavailable | error | stale.
0 допустим только при valid и подтверждённом нулевом количестве; 0/0 = unavailable, не 0%.
Нет данных ≠ ноль ≠ нет активности. Для retention проверять состав когорт, не заменять отсутствующие когорты нулём.
Разделить «всего в базе», «за период», «запланировано», «завершено».
Подтверждённая активность: только подтверждённые события/задания/результаты; отдельно показывать цифровые взаимодействия и не объявлять их реальными результатами.
При отсутствии достаточных данных не строить вводящие в заблуждение тренды, проценты и индексы.
Для каждого агрегата указывать знаменатель и источник. Доступ к персональным drilldown — только по серверным правам.

## 4. Индексы
Пульс, эффективность и пять направлений оставить лишь после аудита формул. Показывать методику, веса, покрытие выборки, дату расчёта. Не представлять субъективные баллы как объективный факт. При выборке меньше порога скрывать чувствительные агрегаты.

## 5. UI
Telegram WebApp responsive 320–430 px; безопасные отступы, учёт верхней панели и нижней навигации. Контраст WCAG AA; размер целей касания >=44px; читаемые подписи; системные шрифты; поддержка светлой/тёмной темы Telegram.
Цвета: белый/нейтральный фон, фиолетовый бренд-акцент, зелёный успех, оранжевый внимание, красный просрочка; не кодировать смысл одним цветом.
Карточки KPI: значение, подпись, динамика только если сравнима, статус данных, tap-to-drilldown. Для empty/insufficient — спокойное объяснение и релевантное действие. Не показывать декоративные 0%-прогресс-бары.
Графики: линейный для динамики, горизонтальный bar для сравнения, stacked bar для статусов; tooltip с точной датой и числом, оси, легенда, альтернативное текстовое описание.
Предупреждения: дедупликация, приоритет, источник, переход к объекту, действие; кнопка не должна быть фиктивной.

## 6. Backend/API
Проверить существующие endpoint, auth Telegram initData, RBAC, SQL-агрегаты, timezone Asia/Yerevan. Переиспользовать существующие сервисы вместо параллельной системы.
Рекомендуемый контракт GET /api/admin/analytics/v2/overview?from=&to= и детальные endpoints только после согласования с текущим роутингом.
Фильтры должны быть параметризованы; лимиты периодов; защита от N+1; кэш с контролируемым TTL и явной датой обновления. Исторические данные не выдумывать и не восстанавливать из текущего состояния.
Серверная проверка роли на каждом endpoint и экспорте; не полагаться на скрытие кнопки.

## 7. PDF и Excel
PDF A4: обложка ЭРА, период/время, executive summary, KPI, динамика, риски, рекомендации, разделы, методика, приложения. Кириллица и армянский Unicode; переносы, номера страниц, дата генерации, единые шрифты. Не обрезать графики и подписи. Excel: отдельные листы по сущностям, заголовки, фильтры, единицы, исходные статусы, без бессмысленных нулей.
Экспорт строго в пределах прав; не включать телефоны, персональные заметки, анкеты и другие персональные поля по умолчанию. PDF/Excel должны совпадать с выбранными фильтрами.

## 8. Тесты и выпуск
Unit: 0/0, пустая база, одна запись, timezone, границы дат, архивные/заблокированные, сравнения.
Integration: RBAC, корректность SQL, экспорты, UTF-8, отсутствие утечек.
E2E: iPhone Telegram WebView, длинные названия, скролл, меню, drilldown, PDF.
Порядок: аудит кода → ветка → реализация по модулям → тесты → review → staging/preview → проверка → продакшн через контролируемый merge. Rollback — предыдущий стабильный commit/deploy.
Критерий приёмки: никакой вводящей в заблуждение нулевой метрики; все кнопки рабочие; 59 существующих метрик доступны; PDF читаемый; права соблюдены; существующие сценарии бота не нарушены.


## 9. Дополнения по фактическим скриншотам Mini App от 21.10.2026 (обязательные)
### 9.1. Учёт ВСЕХ публикаций Telegram-канала
- Метрика «Публикации в канале» считает ВСЕ опубликованные посты в официальном канале ЭРА независимо от автора: администратор вручную, бот, другой сервис, отложенная публикация.
- Источник — события `channel_post` Telegram Bot API в канале, где бот назначен администратором с необходимыми правами. Обрабатывать также `edited_channel_post` без повторного инкремента; media group/альбом учитывать как одну публикацию по заранее документированному правилу, сохраняя идентификаторы сообщений. Не смешивать с сообщениями чата.
- Хранить `chat_id`, `message_id`, `media_group_id`, `published_at`, `edited_at`, `deleted_state` (если достоверно известен), `source_type` (если определим), timestamps. Уникальный ключ `(chat_id, message_id)`; идемпотентный upsert при повторах webhook/update. Не сохранять лишний персональный контент.
- Считать всего и за 7/30/90 дней, дневной график, последний учтённый пост и время последнего события. При отсутствии доступа к каналу показывать «Нет подключения/нет данных», а не 0.
- Telegram Bot API НЕ предоставляет полную произвольную историю канала и не гарантирует уведомления об удалениях: исторический импорт только из реально доступного проверенного источника, без выдуманных чисел. Отдельно указывать дату начала надёжного сбора и покрытие. Проверить права бота и allowed_updates/webhook/polling, чтобы события не терялись.

### 9.2. Сообщения общего чата ЭРА
- Отдельный показатель «Сообщения в общем чате»: число сообщений за период (7/30/90 дней), всего с даты начала сбора, ежедневная динамика и уникальные отправители только при достаточных правах и безопасной агрегации.
- Учитывать ВСЕ доступные сообщения общего чата от участников и администраторов, а не только сообщения, отправленные ботом. Исключить service messages, при необходимости отдельно считать сообщения ботов; явно определить, считать ли темы форума целиком (по умолчанию все темы общего чата).
- Источник — события `message` Telegram Bot API для конкретного chat_id. Проверить privacy mode бота, членство/админские права и webhook `allowed_updates`. При неполном доступе не отображать искусственный ноль. Идемпотентность по `(chat_id, message_id)`, границы дней Asia/Yerevan, хранение минимального набора данных.
- Если уже есть журнал событий, переиспользовать его, а не заводить второй несовместимый счётчик. Ручные сообщения, медиа, сообщения в темах и посты других администраторов должны попадать в соответствующие агрегаты. Отредактированные сообщения не дублировать. Исторический период до начала сбора не восстанавливать без проверенного источника.

### 9.3. Визуальные и логические ошибки по скриншотам
- Исправить несогласованность «67 текущий состав» и «68 участники»: вывести точные определения и синхронизировать фильтры/статусы, либо подписать «67 подтверждённых» / «68 всего записей».
- «Активность 0 · 0.0%», «Медиа 0 сообщений», «Публикаций 1» не должны трактоваться как доказательство отсутствия реальной активности, если Telegram-источники не подключены. Показать покрытие, дату начала отслеживания и статус подключения.
- «Эффективность 0» рядом с «Пульс 79 при выборке 5/67» визуально вводит в заблуждение. Развести операционную эффективность и опросный индекс, указать источники/веса; выборку 5 (7%) выделить как ограничение репрезентативности.
- «0% вышло вовремя» при отсутствии знаменателя заменить на «Нет данных», «0/6 задач» оставить только при подтверждённом факте; не смешивать задачи с публикациями.
- Убрать декоративные круговые индикаторы у метрик, где это не процент; избегать тяжёлых карточек, пустых колец и длинной прокрутки. Главный экран: компактные KPI, график публикаций/сообщений, важные риски, быстрый экспорт. 59 метрик — в раскрываемых тематических группах.
- Кнопки «Сделать сейчас» должны реально вести в соответствующий раздел/создание задачи/события/проекта; иначе заменить на неинтерактивный текст рекомендации.
- Раздел «Медиа» разделить на: публикации канала (все источники), сообщения общего чата, контент-план, выполнение задач медиа. Показывать период для каждой цифры и точное определение.
- Исправить текстовую несогласованность «PDF и Excel — в начале раздела/после главных показателей» и убрать повторные непонятные кнопки «Здоровье». Экспорт PDF должен оставаться заметным и понятным.
- Навигацию по аналитике оформить как компактные переключаемые вкладки, а не несколько рядов больших ссылок. Учесть фиксированную Telegram-шапку и нижнее меню, безопасные отступы и размер касания.
- Никаких фиктивных данных, метрик из памяти или вручную придуманных исторических чисел. Проверять результаты на реальных API и Telegram событиях.

### 9.4. Приёмочные проверки
1. Администратор публикует вручную в канале → публикация учитывается один раз; публикация через бота → тоже один раз.
2. Участник пишет в общий чат (включая тему) → счётчик увеличивается; сообщение бота обрабатывается согласно явной политике.
3. Редактирование/повторное событие не увеличивает счётчик; альбом учитывается по документированному правилу.
4. При отсутствии прав или Telegram-событий UI честно показывает статус источника и начало периода наблюдения.
5. PDF и Excel содержат обе новые метрики и совпадают с экраном по периоду и определению.
6. На iPhone интерфейс не перекрывается Telegram-шапкой, графики читаемы, кнопки выполняют действие.
