## P0 — сохранение действующих функций
- Тема `Мероприятия` использует прежний ключ `announcements` и сохранённый Telegram thread_id. Не создавать дубликат и не переименовывать вручную изменённую тему.
- Тема `Оповещения` использует ключ `notifications`. Рассылки отправляются туда, мероприятия — в `Мероприятия`, цитаты не дублируются в общий чат.
- Исправить PR #317 по созданию событий: отсутствие длинного описания не блокирует сохранение и публикацию; проверить обработку ошибок, права бота и идемпотентность.
- Книжный клуб сохраняет ежедневный график, прогресс, баллы, подписку и 48 авторских разборов; исключить недостоверное заявление о правах на полный текст. Сторонние файлы с неустановленными правами не рекламировать как разрешённые копии.

## P1 — 🎮 Интерактив
- Меню: `🎲 Досуг` → `📚 Литература` / `🎮 Интерактив`; отдельная тема форума `🎮 Интерактив`.
- Флаг `FEATURE_GAMES` = OFF/TESTERS/ALL. OFF по умолчанию, до успешной приёмки.
- Одиночные игры: каждый раунд доступен только участнику, повторные нажатия не дают дополнительных очков; ограничение времени.
- Командные игры: 2–8 реальных участников, одно ожидание не дольше 180 секунд, явное завершение пустых и истёкших комнат; защита от параллельных входов.
- Матчмейкинг без фиктивных игроков и счётчиков. Показывать правдивый статус комнаты.
- Баллы начисляются через существующий `points_service.add_points` с постоянным `idempotency_key`, лимитами и проверкой пользовательской регистрации; отсутствие баллов за одно только ожидание.
- Контент: не менее 11 согласованных форматов и утверждённый разнообразный контент на 180 дней; не объявлять готовность при наличии лишь 8 демонстрационных вопросов. Не расходовать вопросы на отменённые комнаты без продуманной политики.
- Публичное объявление публикуется однократно в `Оповещения`, кнопка ведёт в тему `🎮 Интерактив`, только после подтверждения доступности меню и темы.
- Удалить устаревшее название «Игровая» из всех текстов, клавиатур и тестов.

## P2 — проверки
- Unit: проверка названий тем и ключей, прав доступа, OFF/TESTERS/ALL, callback данных, гонок и дублей, пустых комнат, окончания времени, баллов, ограничений, отсутствия повторных уведомлений.
- Integration: Postgres, scheduler, aiogram router, имитация ошибок Telegram API и перезапуска процесса.
- E2E: пользовательская регистрация, создание мероприятия, подписка на литературу, чтение/задание, командный раунд, повторные нажатия, переход из оповещения.
- CI: все workflow зелёные, без пропущенных критичных тестов.

## P3 — production
1. Проверить diff и CI каждого PR; исправить конфликты с main.
2. Слить только готовые PR; незавершённый интерактив оставить выключенным.
3. Дождаться Render deploy status `live` для конкретного merge SHA, изучить runtime logs.
4. Проверить живой Telegram: кнопки, темы, публикации, реальные callbacks, идемпотентность.
5. Включать FEATURE_GAMES=TESTERS, затем ALL только после прохождения smoke test и готовности контента.
6. Подтверждать завершение только с SHA, Render deploy ID и результатами проверки Telegram; иначе честно указывать оставшиеся блокеры.
