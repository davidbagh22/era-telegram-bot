# Безопасный выпуск синхронизации заданий мероприятий

Привязка: Issues #523, #575, #581. Без удаления данных и перерасчёта баллов.

## Включение

В production фоновая синхронизация **выключена для всех мероприятий по умолчанию**. Параметр конфигурации `EVENT_WIZARD_SYNC_EVENT_IDS` — список числовых ID мероприятий, отдельно подтверждённых для запуска. При пустом значении планировщик не открывает соединение с базой и не создаёт или меняет задания.

Порядок приёмки: (1) 6/6 CI, включая проверку конкурентных операций на PostgreSQL; (2) автоматический выпуск точного SHA; (3) чтение production только на чтение и анализ ID заданий, истории и существующих начислений; (4) подтверждение ограниченного перечня ID; (5) включение через стандартный управляемый выпуск конфигурации, по одному мероприятию; (6) проверка отсутствия дублей, показов, баллов и последствий на реальных данных, затем расширение списка. Никакого автоматического массового восстановления без проверки.

## Инварианты

- Блокировка **Event → EventExperience** для согласования с редактором, без обратного порядка.
- После получения блокировки перечитывается JSON ID; параллельные синхронизации не создают одну задачу дважды.
- Некорректные JSON, пустые/дублированные ID и невалидные значения баллов не должны менять существующие задания.
- CI с PostgreSQL подтверждает восстановление, повторный запуск и гонку двух процессов; это **не** заменяет проверку production.
- Старые записи не удаляются и баллы не корректируются автоматически.
